# Sheriff Rules

- **Election**: During *Preparation* (or as soon as possible afterwards), the table votes to assign the Sheriff badge. The chosen player cannot refuse; the badge sits on top of their role token.
- **Voting power**: While the badge is held, that player’s vote counts as two and they break ties.
- **If the Sheriff is eliminated**: the badge leaves that role. By default it returns to the badge pool. A new Sheriff must be appointed during the next daytime phase (*First day* or *Each day*). If no successor is chosen, the badge remains unused for the rest of the game.
- **If the Idiot was the village' Sheriffs**: The honor will not be passed on -and thus its ability is lost for good.
- **Successor on death**: When eliminated, the Sheriff can name a successor with their “dying breath.” If they do not (or cannot), the badge returns to the pool.
- **Badge handling in play**: The badge token should remain visibly attached to the current Sheriff’s role token. If the badge is lost, place it back in the action panel so it can be reassigned (only during daytime).


These rules synthesize the Sheriff description from the honorary roles data and align them with the app’s phase flow and token handling.
